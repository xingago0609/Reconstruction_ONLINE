# 重組天史：公開發表同步

四位玩家連到同一個伺服器及八碼房間。一人選定公開的卡片後，其他人的公開資料、學術交流選項、相關共同目標會自動更新。正常連線時，每秒檢查一次更新，另加網路傳輸時間。

本功能不傳送玩家的私人手牌、行動點、班級座號或組員姓名。伺服器只儲存自行輸入的暱稱、房間成員與公開卡片。學術交流仍依原有規則消耗行動點。原本理論 06 公開後解鎖現象 10、11 的特殊效果也保留。

## 平板瀏覽器操作

1. 四台平板開啟 https://xingago0609.github.io/Reconstruction_ONLINE/ ，確認遊戲內有「連線房間」按鈕。
2. 開啟右上角「連線房間」。四台輸入同一個伺服器網址與各自暱稱。
3. 一人按「建立房間」，將八碼代碼告訴另外三人，三人按「加入房間」。
4. 關閉連線視窗，照原遊戲流程操作。公開時仍選定要公開的卡片，其餘玩家不必再手動登記。
5. 若網路短暫中斷，尚未送達的公開操作會在同一台手機上保存並重試。公開區以伺服器確認的結果為準，離線期間不假裝已同步。請等待連線恢復再繼續需要共同公開資料的步驟。

晚加入會補齊此房間的公開資料。相同卡片只保留首次發表者，不自動計算或新增聲望，沿用原本桌遊計分。連線恢復不會還原私人手牌與行動點；本功能不是完整的遊戲存檔。

每間房最多四個玩家身分，有效期為建立後 24 小時。玩家暫離仍保留席位；不會因手機短暫切到背景而踢出。換手機或清除 App 資料會失去原席位的身分憑證，需重新建立房間。若要開始新局，使用「離開房間並返回首頁」，並讓四位玩家加入新房間；不要沿用上一局代碼。

## 同一 Wi-Fi：教室電腦執行（原生 App 或本機測試）

GitHub Pages 的 HTTPS 網頁應連接下方的 HTTPS 雲端服務。瀏覽器會阻擋從 HTTPS 遊戲呼叫一般 HTTP 區網伺服器；以下 HTTP 方式主要供原生 App 或本機測試使用。

安裝 Node.js 22 或更新版本，在本資料夾執行：

```powershell
node server.mjs
```

也可以執行 `Start-LAN.ps1`，它會列出電腦的區網 IP。四台手機填入例如 `http://192.168.1.20:8787`，實際 IP 以電腦為準。手機不能填 `localhost`，那會指向手機自己。

電腦與手機需在能互相存取的網路上；電腦必須維持開機及服務運作。若 Windows 防火牆詢問 Node.js 的區域網路連線，可允許目前使用的私人網路。校園 Wi-Fi 若開啟用戶端隔離，改用允許裝置互連的 Wi-Fi，或使用下方雲端方式。本腳本不自動變更防火牆。

用手機瀏覽器開啟 `http://電腦IP:8787/health`，應看到 `"status":"ok"`，再進遊戲輸入相同網址（不加 `/health`）。

## 跨網路：Render 雲端部署方案

建議先在本機完成手機驗收，再部署正式服務。正式課堂使用可選 Render 的一個付費 Node Web Service，搭配持久磁碟；所需費用以建立服務時的報價為準。本次提供設定檔，沒有代為註冊、購買或發布服務。

1. 本服務位於 `xingago0609/Reconstruction_ONLINE` 儲存庫的 `PublicSyncServer` 資料夾。不要上傳 `data/`。
2. 登入 Render，新增 Web Service 並連接該儲存庫，Root Directory 填 `PublicSyncServer`。
3. Runtime 選 Node；Build command 為 `node --version`，Start command 為 `node server.mjs`。指定 Node 22。
4. 選擇一個付費服務實例，維持 **單一實例**。新增持久磁碟，mount path 為 `/var/data`；環境變數 `DATA_FILE=/var/data/rooms.json`。健康檢查路徑 `/health`。
5. 部署完成後，用 Render 提供的 HTTPS 網址測試 `/health`。四台手機輸入這個 HTTPS 網址與相同房間代碼，就能跨 Wi-Fi／行動網路遊玩。
6. 也可用儲存庫根目錄的 `render.yaml` 透過 Blueprint 建立上述配置；建立前先查看服務與磁碟費用。

免費 Render 服務適合短暫測試，但有休眠與非持久檔案系統限制。這份實作使用檔案保存房間，正式服務必須掛載持久磁碟，否則重啟／重新部署可能失去房間。

來源：[Render Node 部署](https://render.com/docs/deploy-node-express-app)、[持久磁碟](https://render.com/docs/disks)、[免費方案限制](https://render.com/docs/free)。文件查核日期：2026-09-17。

其他主機也可使用 `Dockerfile`，將可寫的持久目錄掛載到 `/data`，並在前端設定有效 HTTPS 憑證。這個 JSON 狀態檔的設計只支援單一伺服器程序；請勿同時開多個副本共用檔案。

## Unity 整合與驗收

維持 Unity 2019.2.10f1，不要求升級 Unity 或安裝 Photon。新連線元件會在遊戲啟動時自行建立，不需手動掛到場景。UI 字型引用原專案的 Taipei Sans TC。可以在 `Assets/Resources/PublicSyncSettings.asset` 填入固定的伺服器網址，減少手機端輸入。

新增 Android Manifest 允許網路及教室 HTTP；手機端只允許區網 IP 使用 HTTP，公開網址需 HTTPS。現有場景與卡片素材不更動。

四台實機驗收：

- A 公開現象 04，B/C/D 的公開區可查到，學術交流可選；不直接取得私人手牌。
- A 選擇不公開時，B/C/D 不更新。
- B 學習卡片後，後續同步不會重新打開已用掉的交流選項。
- 公開理論 02–05 後，四台共同目標皆依原规则更新。
- D 暫時斷網，其他玩家公開，再恢復 D 的網路，D 補齊所有公開資料。
- 發表端暫時斷網，點選公開，恢復後只送出一次。
- 兩位玩家同時公開同一卡片，房間只記錄一次。
- 改成一台 Wi-Fi、另一台行動網路，透過雲端 HTTPS 重做以上測試。

## 開發測試與運維

```powershell
node --test server.test.mjs
```

服務預設監聽 `0.0.0.0:8787`，可用 `PORT`、`HOST` 改寫；資料檔預設 `data/rooms.json`，可用 `DATA_FILE` 改寫。請保留持久磁碟，並在沒有進行中的遊戲時更新伺服器。房間代碼請僅提供同組玩家。
